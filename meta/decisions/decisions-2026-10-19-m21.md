176. **Waiting for a long run (replaces decision 159 (d)'s wait).** The
     harness refuses the lone `sleep 240` that 159 (d) prescribes. HF-015's
     status line of mission 20 U1 and REVIEW-20 note 8 both record the
     refusal. Mission 20's sub-agents waited instead with one foreground
     poll call, and that call was admitted. So that call is now the wait.
     A `./scripts/check`, `./scripts/gate` or `./scripts/speed` run that
     the harness moves to the background at the 20-minute cap is waited
     for as follows:
     - one foreground Bash call, with a timeout of at most 20 minutes, that
       polls the run's output file until the run's last line is there (for
       example `timeout 1100 bash -c 'until grep -q <last-line pattern>
       <output file>; do sleep 15; done'`);
     - then one read of the whole file;
     - repeated until the run has ended.

     A sub-agent never starts a Monitor or a background task to wait. It
     never reports before the run has ended. The run is recorded as
     decision 145 says.
